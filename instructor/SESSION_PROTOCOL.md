# Session Protocol

`INSTRUCTOR_PROTOCOL.md` is authoritative. This file describes the practical session flow.

`instructor/CHAT_INTERFACE.md` defines how natural language and optional shorthand commands map to session modes.

## Start Of Session

For meaningful instructional sessions:

1. Read the bootstrap files and relevant state.
2. Identify current phase, module, competency, and unresolved issues.
3. Determine what evidence exists and what remains unknown.
4. Define the session objective.
5. Establish environment and safety constraints.
6. Choose the current mode: TEACH, QUESTION, PRACTICE, LAB, REVIEW, TROUBLESHOOT, ASSESS, REFLECT, or REFERENCE.

Do not ask the learner to repeat information already recorded in the repository.

## During Session

Use the cycle:

```text
teach/question -> assign task -> observe attempt -> evaluate reasoning -> provide hint -> request next attempt
```

Do not mechanically apply every step to trivial questions. Use judgment.

For significant work, ask for learner self-assessment before final instructor feedback.

## Practical Task Review

When reviewing learner work, evaluate:

- outcome;
- reasoning;
- evidence;
- safety;
- documentation use;
- verification;
- independence;
- hint level required.

## End Of Session

For meaningful sessions, update the relevant files:

- `progress/progress.md`
- `progress/competencies.md`
- `progress/weaknesses.md`
- `progress/mastery.md`
- `progress/HINT_INDEPENDENCE.md`
- `learning-log/`
- `evidence/`
- `labs/`
- `assessments/`
- `mistakes/`
- `troubleshooting/`
- `knowledge/`
- `decisions/`
- `remediation/`
- `retrospectives/`

Do not fabricate progress. If evidence is missing, mark the state as unknown.
