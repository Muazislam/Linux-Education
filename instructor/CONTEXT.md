# Stable Learner Context

This document contains stable educational context. Behavioral rules live in `INSTRUCTOR_PROTOCOL.md`; do not duplicate them here.

## Learner Profile

The learner is studying full-stack web development as the primary career track. Current development progression is approximately:

```text
HTML -> CSS -> Bootstrap -> JavaScript -> React -> Node.js -> Express -> databases -> APIs -> authentication -> testing -> deployment -> advanced full-stack engineering
```

Linux is a secondary but serious track. It must support employability as a full-stack developer rather than consume all available study time.

## Educational Goals

The learner wants to develop genuine Linux/Unix engineering competence, not memorize commands. The desired end state is the ability to operate, understand, diagnose, maintain, secure, automate, and recover Linux systems.

## Technical Goals

The curriculum should build competence in:

- Unix/Linux fundamentals;
- command-line workflow;
- shell scripting;
- filesystems and permissions;
- processes and jobs;
- users, groups, and privilege;
- systemd and services;
- package management;
- logs and observability;
- networking;
- SSH and remote systems;
- storage;
- boot and recovery;
- security;
- backups;
- virtualization;
- Docker;
- Arch Linux administration.

## Arch Linux Goals

The learner currently uses EndeavourOS and eventually wants to understand Arch Linux well enough to install and administer it independently. Arch-specific work should be grounded in general Linux concepts and ArchWiki documentation.

## Troubleshooting Goals

The learner should become comfortable with failure and use this process:

```text
STOP -> OBSERVE -> PRESERVE EVIDENCE -> FORM HYPOTHESES -> TEST -> ISOLATE -> REPAIR -> VERIFY -> DOCUMENT
```

## Professional Engineering Goals

The Linux track should reinforce full-stack development through practical connections:

- shell workflow for development;
- processes and ports for Node.js;
- environment variables for app configuration;
- logs for backend debugging;
- permissions for file uploads;
- SSH for remote development;
- Docker for local infrastructure;
- systemd/reverse proxy concepts for deployment when appropriate.

## Independence Goals

The learner should progressively require fewer high-level hints, consult documentation earlier, explain reasoning clearly, verify changes, and recover from realistic failures without panic.
