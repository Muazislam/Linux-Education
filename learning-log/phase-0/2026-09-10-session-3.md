# Learning Session: Phase 0 - VM Sandbox, Snapshot Verification, Rsync Backups & Host Baseline

## Date
2026-09-10

## Module
Phase 0 - Environment, Safety, and Baseline Setup

## Topic
VirtualBox Arch VM Setup, Snapshot Lifecycle Verification, Host Backup Strategy via Rsync, and Full Host Telemetry Baseline

## Objective
Establish complete safety boundaries for destructive labs: configure a disposable Arch Linux VM with snapshot capability, verify host data backup with `rsync`, collect baseline host telemetry, and complete the Phase 0 Safety Checklist.

## What I Studied & Practiced
1. **Disposable Lab Virtualization**:
   - Evaluated virtualization options and selected Oracle VirtualBox instead of QEMU/KVM to avoid modifying host firewall settings before acquiring necessary networking depth.
   - Booted Arch Linux ISO (`arch-lab-01`, kernel 7.2.4-arch1-2) into a pure headless/CLI console (`tty1`). Clarified that a GUI is not required for deep systems engineering, kernel concepts, or administration.
   - Managed users (`root` and `muaz` creation with `useradd`).
2. **Snapshot Lifecycle & Recovery Verification**:
   - Created snapshot `phase-0-base`.
   - Tested filesystem modification inside the guest by creating `/root/snapshot-test.txt`.
   - Restored snapshot `phase-0-base` and verified that the guest reverted cleanly to the baseline snapshot state.
3. **Storage & Host Backup with `rsync`**:
   - Partitioned external storage (`/dev/sdc`) and formatted partition `sdc1` with `ext4`.
   - Tested `rsync` dry-runs (`--dry-run -av`) and directory exclusion flags (`--exclude='node_modules/'`).
   - Performed real data synchronization copying ~487 MB of critical host directories to external backup.
4. **Host Diagnostic Baseline Collection**:
   - Captured full host state across 9 key subsystems: OS release, kernel, CPU topology, memory utilization, disk partitions, filesystem usage, systemd failed units (0 failed), package integrity via `pacman -Qk` (0 missing files), and network interfaces/routes.
   - Identified and analyzed boot journal entries, including ATA write errors on the external test drive `/dev/sdc` (since resolved).
5. **Privacy & Repository Discipline**:
   - Initialized `.gitignore` and established an untracked `private/` directory for un-redacted machine telemetry and private logs.

## What I Discovered & Clarified
- CLI-only environments are ideal for mastering Linux fundamentals without desktop environment abstractions.
- Snapshots provide an instantaneous rollback gate that makes destructive learning safe.
- `rsync` trailing slashes (`source/` vs `source`) dictate whether the directory itself or its contents are mirrored.
- Hardware errors and filesystem mount anomalies immediately surface in kernel rings (`journalctl -b -p err` / `dmesg`).
