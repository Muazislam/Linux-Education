## Objective
Decode and interpret standard UNIX file permission triplets, attribute ownership and group associations from directory listings, and understand the functional distinction between file execution and directory execution.

## What I Practiced & Explored
1. **Mode String Deconstruction**:
   - Analyzed the leading byte: `-` (regular file) vs `d` (directory) vs `l` (symlink).
   - Deconstructed the 9-character permission triads into the 3 discrete identity domains:
     - **User/Owner (`u`)**: First triplet (`rw-` $\rightarrow$ read and write allowed, execution disabled).
     - **Group (`g`)**: Middle triplet (`r--` $\rightarrow$ read-only for group members).
     - **Others/World (`o`)**: Final triplet (`r--` $\rightarrow$ read-only for all other accounts).
   - Clarified that `-` represents an ungranted/disabled permission bit.
2. **Owner and Group Association**:
   - Identified owner (`muazislambabar`) and primary group (`muazislambabar`) from column positions in standard `ls -l` listings.
3. **Directory Traversal Semantics (`x` on directories)**:
   - Discovered that the execute (`x`) permission on directories does not execute a binary; instead, it grants entry/traversal rights (allowing a user to `cd` into the folder and access files within it).
   - Contrasted with directory read (`r`), which only permits listing file names without accessing contents if `x` is absent.
4. **Live Verification**:
   - Executed `ls -ld ~/Downloads` on host. Verified `drwxr-xr-x 1 muazislambabar muazislambabar` and inspected full permission string.
5. **Documentation Searching**:
   - Investigated `man -k` phrase queries, identifying that multi-word queries require quotes (e.g. `man -k "file mode"`).
